# Template Workspace V2: Word-first editor by example

## Текущее состояние

`/template/v2/` — отдельный Word-модуль (статья DOC/DOCX, шаблон DOC/DOCX/DOTX), который получает черновик
`ARTICLE` и хорошо оформленный `TEMPLATE`, извлекает из шаблона роли и правила
вёрстки и редактирует копию исходного Word-файла. Модуль уже создаёт
`result.docx`; старое описание V2 как read-only инспектора больше неактуально.

Основной контракт:

```text
ARTICLE.docx + TEMPLATE.docx
  -> DocumentInspector (только факты исходного OOXML)
  -> RoleClassifierV2 (детерминированные роли ARTICLE)
  -> TemplateProfile + LayoutProfile (правила оформления TEMPLATE)
  -> QwenLikePlanningEngine (локальный план + необязательный Qwen-патч)
  -> строгая whitelist-валидация плана
  -> SafeWordEditor (минимальные изменения копии ARTICLE)
  -> исходный безопасный result.docx + layout_targets
  -> quality_cycle: PDF-render + Qwen vision + структурная проверка
  -> разрешённые адресные правки отдельной копии (не более двух раундов)
  -> повторный render/QA -> принятие улучшения или откат
  -> лучший проверенный кандидат + отчёт качества, отдельно от охвата
```

V1 на `/template/` остаётся старым конвертером через `ConversionPipeline` и
`ArticleIR`. Не подключать V1 renderer как ядро V2: пересоздание документа из IR
теряет слишком много Word-специфики.

При визуальном контроле сравнивать также серверный LibreOffice PDF: Word может
удерживать составной рисунок, который LibreOffice разбивает между страницами.
Исходный ряд из двух-трёх inline-панелей с общей ближайшей подписью получает
полноширинную секцию, если ряд шире 1.55 колонки и помещается в 96% печатной
ширины. Явные переносы, формулы и OLE не перестраиваются. Только в полноширинной
области `wrap_picture_captions` может удерживать такой ряд вместе с подписью.
Не помещать высокий стек картинок в `cantSplit`-таблицу узкой колонки:
LibreOffice может обрезать его, несмотря на целый DOCX. Повторная PDF-проверка
отклоняет кандидата, если из извлечённого PDF пропали ранее видимые текстовые
фрагменты/подписи (`rendered_content_regression`); это дополнительный барьер,
а не замена визуальному контролю изображений.

## Безопасная граница

Источником содержания всегда остаётся `ARTICLE`. Редактор сохраняет его
таблицы, DrawingML, media, OMML-формулы, OLE, hyperlinks, numbering и package
relationships. Нативные узлы перемещаются целиком; рисунки, формулы и таблицы
не пересобираются из текста.

Из `TEMPLATE` разрешено брать:

- эффективное форматирование структурных ролей;
- геометрию страницы, поля и колонки;
- закономерности одноколоночных/двухколоночных секций;
- безопасную журнальную оболочку header/footer;
- рубрику/служебный layout shell только там, где это общая часть макета.

Нельзя выдавать авторов, DOI, цитирование, биографии, даты поступления,
лицензионный блок или другие данные чужой статьи за данные `ARTICLE`. Для
ограниченного набора редакционных идентификаторов (`УДК`/`UDC`, `DOI`) действует
явное правило placeholder: если поле отсутствует в `ARTICLE`, V2 переносит
соответствующее поле из верхней идентификаторной строки `TEMPLATE` и целиком
выделяет его жёлтым. Такое значение предназначено только для последующей замены
редактором и одновременно записывается в warning/editor report. Реальное значение
`ARTICLE` всегда имеет приоритет. Авторы, заголовок, цитирование и основной текст
из шаблона по-прежнему не копируются. Header/footer копируется только если из
ARTICLE надёжно извлечена короткая строка авторов для санитизации footer.

## Qwen через production VPN

Qwen не редактирует DOCX и не пишет текст. При
`TEMPLATE_V2_QWEN_ENABLED=1` класс `QwenPlanningProvider` отправляет компактный
семантический snapshot через общий OpenAI-compatible клиент. Серверный путь:

```text
Django/webtstu -> tun0 -> openvpn-client@vrlab
  -> TEMPLATE_V2_QWEN_BASE_URL или общий AI_BASE_URL
  -> POST /v1/chat/completions
```

Ответ модели — только JSON-поправка к `front`/`flow`. Планировщик принимает
только известные поля, детерминированно допустимые ID таблиц ARTICLE,
boolean-значения и числа в заданных диапазонах. Локальный план является полом
качества: front matter полностью задаётся доказательствами TEMPLATE, а модель
не может отменить защитные решения, добавить новый page-break candidate или
расширить лимиты флотирования. Текст, XML, незнакомые
ключи и выдуманные ID игнорируются. При timeout, ошибке JSON, недоступности VPN или модели редактор
автоматически использует локальный детерминированный план и записывает warning.

Настройки:

```dotenv
TEMPLATE_V2_QWEN_ENABLED=1
TEMPLATE_V2_QWEN_BASE_URL=http://192.168.92.20:8088/v1
TEMPLATE_V2_QWEN_MODEL=qwen3.8-27b-vision
TEMPLATE_V2_QWEN_TIMEOUT=300
```

`DocumentInspector` и `RoleClassifierV2` остаются offline и воспроизводимыми.
На 2026-09-12 оба endpoint работают: 1234 (`qwen3.5-9b`) и 8088
(`qwen3.8-27b-vision`). Каждый прошёл реальные запросы на четырёх новых парах.
Общий `AI_BASE_URL` сайта не переключается. Snapshot ограничен 22000 символами;
переполнение старого контекста 20k токенов на длинной статье исправлено.
На 2026-09-13 добавлен отдельный post-render vision QA (`v2/readability.py`).
Планировщик по-прежнему получает только JSON; проверяющий получает две
перекрывающиеся половины каждой выбранной страницы PDF. Текст документов —
недоверенные данные, не инструкции. Модель сообщает замечания, но не меняет
научное содержание и не выполняет произвольные операции над XML.

```dotenv
TEMPLATE_V2_VISUAL_REVIEW_ENABLED=1
TEMPLATE_V2_VISUAL_REVIEW_MAX_PAGES=8
TEMPLATE_V2_VISUAL_REVIEW_PAGE_TIMEOUT=300
TEMPLATE_V2_VISUAL_REVIEW_BUDGET=900
TEMPLATE_V2_EDIT_CYCLE_ENABLED=1
TEMPLATE_V2_EDIT_CYCLE_MAX_PASSES=3
TEMPLATE_V2_EDIT_CYCLE_BUDGET=2100
```

В settings проверка по умолчанию выключена; на сервере включается явно.
Первые две страницы включаются в vision первыми (с 2026-09-15), затем приоритет
получают код, таблицы и формулы. Геометрический
контроль границ охватывает до 200 страниц; vision — максимум 40, по умолчанию 8.
Лимит 900 секунд относится к одному vision-проходу. Цикл ограничен тремя проходами
(базовый + максимум две правки), общим бюджетом 2100 секунд и оставшимся временем.
Конвертация Word в PDF имеет собственный тайм-аут и учитывается внешним worker.
Страница vision ограничена 300 секундами (оба front-запроса вместе).
Ожидание очереди входит в эти лимиты: OpenAI-совместимый HTTP-запрос не отделяет
его от генерации. Общий оставшийся бюджет всегда ограничивает тайм-аут страницы.
В отчёте записываются `page_timeout_seconds`, `budget_seconds` и
`queue_wait_included_in_limits`. Это увеличение ожидания, не отдельная очередь
приложения и не автоматический повтор запросов.
Внешний deadline V2 worker вычисляется как минимум 18 минут или сумма двух
AI-бюджетов плюс 10 минут на конвертацию/анализ/render: с циклом при этих настройках
50 минут. Сайт помечает задание зависшим ещё через 2 минуты (52 минуты).
При выключенном цикле сохраняются прежние 30/32 минуты; offline — 18/20.
Legacy-таймер 20 минут применяется только к V1, не к ожидающей V2 job.
Сетевая ошибка endpoint прекращает дальнейшие запросы; некорректный или
обрезанный JSON оставляет только эту страницу непроверенной, остальные проверяются.
Недоступность QA
не блокирует готовый DOCX, но обязательно отражается в отчёте.
`readability_report.json` содержит `pages_checked`, `pages_not_checked`,
`geometry_pages_checked`, замечания и статус `partial/reviewed/unavailable/disabled`.
`reviewed` означает охват, а не отсутствие ошибок или научную экспертизу.
Замечания Qwen рекомендательные: допустимые переносы таблиц тоже могут вызывать
ложные срабатывания. Не выдавать выборочный просмотр за проверку всей статьи.

## Замкнутый цикл редактора (2026-09-16)

Единый `v2/quality_cycle.py` используется сайтом и `manage.py run_template_v2`.
`editor/repair_actions.py` строит после структурных преобразований sidecar-реестр:
ID, путь к нативному узлу, роль, формат TEMPLATE, доступная ширина, известная подпись.
Сам DOCX не получает служебных ID. На PDF-страницу ID попадает только по уникальному
текстовому якорю; повторяющиеся/не найденные подписи не угадываются. Ветка Fallback
не дублирует видимый якорь AlternateContent.

Qwen может добавить к замечанию только `target_id` + разрешённый `action`:
восстановить типографику/параметры абзаца, центрировать/вписать рисунок в текущую
ширину, удержать известную пару рисунок–подпись. Нельзя прислать XML, координаты,
новые слова или произвольное изменение роли. Научные формулы не превращаются в картинки.
Неподдержанные замечания остаются видимыми в отчёте, а не считаются исправленными.

Кандидат создаётся отдельно. Перед записью проверяются точные факты каждого абзаца:
слова/знаки/порядок, индексы, OMML, поля, ссылки, нативные объекты и пробелы кода.
Другие части ZIP, включая media/embeddings/relationships, копируются байт-в-байт.
Хеш защищает от применения плана к другой версии документа. Повторная проверка
не может иметь меньший охват; при выборочном просмотре сама изменяемая страница и
её соседи должны быть проверены до и после правки. Изменение пагинации при неполном охвате отклоняется.
Не принимаются новые серьёзные дефекты, ухудшение геометрии и варианты без измеримого
улучшения. Сбой/тайм-аут отменяет кандидат, не уничтожает готовый базовый DOCX.

`quality_cycle/pass-N/` содержит версии и проверки; `quality_cycle_report.json` —
принятые/отклонённые действия, причины остановки и хеш выбранного DOCX.
`readability_report.json` и PDF-preview относятся к выбранной версии, а не последней
отклонённой. Эти файлы доступны владельцу задания. История исходного задания не заменяется.

`job.status=completed` означает наличие файла, не качество. Отдельный статус:
`checked` — все страницы просмотрены, замечаний нет; `needs_review` — остались замечания;
`partially_checked` — замечаний на просмотренных нет, но охват неполный;
`unverified` — проверка недоступна/выключена. Научная корректность этим не подтверждается.
PDF bbox обрезанного bitmap не считается доказанным выходом рисунка за страницу:
это границы ДО clipping path; видимый результат оценивается по рендеру.

Исправлены причины плохого Tyutyunnik → Balabanov результата: смешанный текст/рисунок
в одном run больше не пропускает формат шрифта; локальные продолжения заголовков
объединяются нативными runs даже при объектах в front matter; большие плавающие
объекты отделяются от прозы, сохраняются оба представления caption textbox, убираются
старые координаты/рамки; крупные неформульные OLE-превью и параллельные биографии
могут занимать полную ширину. Пустая колонка-разделитель не растягивается как данные.

Ограничения: это ограниченный безопасный корректор, не универсальный DTP-оптимизатор.
Он не переводит, не переписывает статью и не исправляет неподдержанные замечания
вольным генеративным редактированием. Word и LibreOffice могут различаться в пагинации.

## Что делает SafeWordEditor

- нормализует порядок bilingual front matter по доказательствам TEMPLATE;
- применяет role-scoped шрифт, размер, интервалы, отступы и выравнивание;
- измеряет и восстанавливает интервалы между названием, авторами, аффилиацией,
  email, аннотацией, keywords и citation, а также вокруг заголовков;
- добавляет только отсутствующие `УДК`/`UDC` и `DOI` как жёлтые placeholders;
- берёт число колонок и поля из TEMPLATE, включая одноколоночный MDPI и A5;
- вставляет временные полноширинные полосы для широких рисунков/таблиц;
- удерживает подписи с inline-рисунками и компактные таблицы от разрыва;
- оставляет описательный текст перед рисунком; переносит только целый рисунок
  с подписью после ближайшего первого упоминания, без перестановки абзацев;
- масштабирует только существующие drawing/table geometry;
- переносит header/footer shell, логотипы и PAGE fields с уникальными именами
  package parts; для JAMT строка над чертой справа и серая (новое указание
  2026-09-15 отменяет прежнее левое выравнивание);
- переносит свойства таблиц из TEMPLATE; согласует grid/tcW, отменяет старые
  абзацные отступы внутри ячеек и учитывает ширину чисел;
- по явному правилу пользователя убирает вертикальные границы научных таблиц,
  включая таблицы с формулами; центрирует значения, описательные столбцы — слева;
- сбрасывает смещение самостоятельных рисунков, переводит floating anchor в
  inline, сохраняет связанные панели и нативные рисунки/подписи;
- материализует скрытые свойства старых Equation-полей; не показывает их
  служебные строки и не превращает OLE-формулы в новый текст;
- проверяет сохранность научных токенов, OMML, объектов, ссылок и исходных media
  до записи результата; ошибка проверки блокирует выдачу повреждённого DOCX;
- сериализует OOXML с каноническим порядком property-узлов.

Защита читаемости (2026-09-13): многострочный JSON/код получает левое
выравнивание без растяжения soft-break строк; символы, пробелы, табуляции и
переносы кода проверяются на точное сохранение. Отдельно стоящие OMML/OLE-формулы
центрируются в текстовой области, inline-формулы не перемещаются. Для номера
формулы цепочки ручных табуляций заменяются двумя ограниченными позициями:
центр формулы и правый край номера. Интервалы берутся из формульного образца
TEMPLATE, при его отсутствии применяется небольшой безопасный интервал.

Широкие таблицы могут занимать полную печатную ширину, если это подтверждено
табличным образцом TEMPLATE. Ширина учитывает заголовки, длинные идентификаторы,
компактный номер строки и диапазоны чисел. Компактные таблицы до 12 строк
удерживаются вместе; длинные продолжаются с повторяемой шапкой. Границы и
отступы наследуются из стиля таблицы, а не только из прямого форматирования;
граница первой группы объединённых строк не размножается на каждую строку.
У header явно материализуются нулевые интервалы шаблона, чтобы линия не
обрезалась из-за docDefaults исходника. Для footer с PAGE/frame это отключено:
изменение его унаследованных интервалов сдвигает нативный номер страницы.

Нельзя вызывать `etree.cleanup_namespaces` перед сохранением Word parts:
совместимые namespace prefix могут использоваться только строкой
`mc:Ignorable`; их удаление делает пакет повреждённым для desktop Word. Также
важен schema-order дочерних элементов `w:pPr`, `w:rPr`, `w:sectPr`, table
properties и `w:settings`.

### Проверка геометрии 2026-09-15

`editor/layout_fidelity.py` исправляет общие причины ошибок, обнаруженные в
`result_9.docx`: пропавшие пустые строки между front-ролями, старый firstLine=709
у рисунков, OMML 16/14 pt при 11 pt body и прежний принудительный левый header.
У образцов JAMT основной отступ 425–426 twips (~0,75 см): нельзя повсюду
подставлять 0,6 см. OMML получает явную типографику формул TEMPLATE, при её
отсутствии — body; OLE-font/binary не редактируется. Gate дополнен проверкой
структуры математических выражений, а не только набора символов.

Word может игнорировать keepNext при балансировке двух колонок перед широкой
таблицей. Умеренный одиночный рисунок и соседняя подпись поэтому оборачиваются
в нативную одноклеточную таблицу без границ с cantSplit. Это увеличивает число
layout-таблиц, но не меняет исходные рисунки, подписи, ссылки и научные таблицы.
Большие рисунки остаются в обычном потоке. A/b пары не сжимаются до нечитаемого
размера только ради полустраницы; сложные графики могут занимать полную ширину.

Qwen для первых двух страниц проверяет две половины отдельными запросами: в
каждом один фрагмент RESULT и явно помеченный верхний фрагмент страницы образца
TEMPLATE. Страница выбирается по заголовку из профиля шаблона: у legacy это
страница 2 после инструкций, у JAMT/MDPI/RUS — 1. Если заголовок не найден,
сравнение с образцом пропускается с предупреждением, первая страница не угадывается.
В ранних прогонах три плотных изображения одновременно давали тайм-аут на JAMT.
Позже пользователь подтвердил здоровый Qwen с единственным занятым слотом:
ожидание очереди ~68 с само по себе превышало прежний лимит 60 с. Нельзя считать
тайм-аут доказательством неисправности VPN/модели или исключительно сложности
изображений. Время ожидания повышено, сервис Qwen перезапускать не требуется.
Страница считается просмотренной только после успеха обоих запросов; они делят
единый 300-секундный лимит страницы. Образец служит источником дизайна, не текста.
Отчёт содержит `template_front_reference_available`, `template_reference_page`
и `template_comparison_pages`.
Проверка не заменяет редактора: нет права переписывать науку, формулы, авторов
или выполнять операции, предложенные текстом документа.

## Иерархические таблицы — 2026-09-15

Запрос по Table 2 (X-ray phase analysis) уточняет политику горизонтальных линий:
таблица с многострочной шапкой и объединёнными названиями групп — не обычная
сетка. В исходном DOCX это одна таблица с `gridSpan`/`vMerge`, не вложенная.

`v2/editor/table_structure.py` читает логические столбцы, вертикальные цепочки
объединений, последовательные `tblHeader` и разбиение горизонтального span
на подзаголовки. Глубина шапки и границы групп не зависят от конкретных слов,
числа компонентов или количества параметров. Группы определяются по левому
текстовому столбцу с реальными вертикальными объединениями; повторяющиеся
слова/пустые ячейки без объединений не являются достаточным доказательством.

`scientific_table_rules` для уверенно распознанной иерархии:

- явно отключает старый `insideH` и внутренние границы ячеек/исключений строк,
  иначе исходный стиль Word снова рисует сетку;
- оставляет верх/низ, линию под **всей** шапкой и между внешними группами;
- не проводит линию сквозь продолжающееся вертикальное объединение;
- повторяет всю шапку при переносе, даёт небольшой внутренний отступ строкам,
  центрирует короткие значения и выравнивает длинные описательные столбцы влево;
- сохраняет все ячейки, объединения, текст, формулы и отношения DOCX.

Настоящий контейнер с вложенными таблицами не получает рамку таблицы данных:
оформляются только уверенно распознанные иерархические таблицы-листья, без
перестройки контейнера. Блоки рисунков пропускаются. При нарушенной топологии
объединений правило не угадывает структуру. Не путать эту осторожность с
поддержкой произвольной ручной вёрстки вложенных таблиц.

Исправлен счётчик inspector: XPath `.//w:tbl` уже исключает сам текущий узел;
вычитать единицу нельзя. Раньше обычные таблицы получали `-1` и ошибочно
попадали в `LAYOUT_TABLE`, а одиночная вложенная таблица не учитывалась.
Шаблонная типографика теперь учитывает многострочную шапку при выборе образца.
`editor_report.json → metrics.table_rule_plans` содержит распознанную структуру.
Qwen получил отдельные критерии групповых линий; он остаётся рекомендательной
проверкой, а не источником научных данных или произвольных XML-операций.

идентичность XML-узла, не поиск по совпадающему тексту ячеек.

  `native_integrity` и точная проверка кода. Удалённый непустой абзац без
