# Извлечение структуры научного документа

Конвейер разделён на два независимых слоя.

1. `document_analysis.py` извлекает наблюдаемые блоки: абзацы и их оформление,
   таблицы, рисунки, OMML/LaTeX-формулы, страницы PDF, служебные области DOCX и
   признаки безопасности. Пользовательский LaTeX не исполняется.
2. `article_extraction.py` классифицирует блоки как название, авторов,
   организации, аннотацию, ключевые слова, основной текст, разделы и
   библиографию. Каждое поле содержит `confidence`, `source_block_ids` и
   `method`.

Совместимый со старым интерфейсом словарь `snapshot["metadata"]` сохраняется.
Полная формат-независимая модель находится в `snapshot["article"]`.

Локальная модель не является первичным парсером. При включённой настройке
`SUBMISSION_DOCUMENT_EXTRACTION_AI_ENABLED=1` она вызывается только для
`needs_review` и может вернуть лишь ID существующих блоков. Текст результата
восстанавливается из документа, поэтому модель не может добавить вымышленные
имена, организации или фрагменты статьи.

PDF с текстовым слоем разбирается через `pypdf`. Для сканов выставляется
`requires_ocr=true`. Старый бинарный DOC сначала конвертируется в изолированной
временной папке: LibreOffice используется на сервере, Microsoft Word с
принудительно отключёнными макросами — как резервный путь в Windows. После
конвертации тот же анализатор DOCX формирует единую модель статьи.

Корпус проблемных файлов можно проверить как папку или без распаковки ZIP на диск:

```powershell
python manage.py audit_document_corpus Novaya_papka_19 --output output/report.json
python manage.py audit_document_corpus examples.zip --output output/report.json
```

После настройки VPN и локального OpenAI-совместимого API:

```powershell
python manage.py audit_document_corpus examples.zip --with-ai --output output/report-ai.json
```
