# Умный поиск источников

Приложение `apps.citations` — отдельный контур RAG для поиска публикаций, которыми
можно подтвердить конкретные утверждения загруженной статьи.

## Как работает

1. Индексатор читает расширенный манифест ТГТУ и десять годовых ZIP с PDF.
   Старый режим с `downloads_elibrary` остаётся доступен для совместимости.
2. PDF разбиваются на самостоятельные смысловые фрагменты. Заголовок, секция,
   ключевые слова и метаданные индексируются вместе с текстом.
3. Анализатор выделяет утверждения без ссылок и классифицирует потребность:
   `topic`, `method`, `data`, `task` или `result`.
4. Для утверждения строятся русскоязычный и англоязычный запросы.
5. Retrieval объединяет SQLite FTS5 и векторную близость. Сначала выбираются
   наиболее релевантные статьи и фрагменты FTS5, затем семантическая оценка
   считается только для этих кандидатов. Если настроен локальный
   `/v1/embeddings`, используются его эмбеддинги; иначе работает полностью
   локальный hashing-вектор.
6. Настроенная локальная LLM проверяет найденные фрагменты, отбрасывает простые
   тематические совпадения и объясняет рекомендацию.
7. Пользователь видит авторов, год, DOI/EDN, процент соответствия, объяснение и
   связанный фрагмент. Аннотации старых карточек eLIBRARY явно помечены; PDF
   расширенного корпуса открывается по постоянной ссылке сайта. Выбранные
   источники можно скопировать или вставить в DOCX вместе со списком литературы.

## Подготовка индекса

```powershell
python manage.py build_citation_index
```

Для расширенного корпуса разместите десять ZIP из папки Drive «Статьи ТГТУ
2022–2026» в отдельном каталоге и задайте:

```dotenv
CITATION_CORPUS_MODE=tgtu_archives
CITATION_TGTU_MANIFEST=/path/to/data/tgtu_corpus/manifest.jsonl
CITATION_ARCHIVE_ROOT=/path/to/tgtu_drive_archives
CITATION_INDEX_PATH=/path/to/citation_index.sqlite3
```

Постройте индекс отдельной командой:

```powershell
python manage.py build_citation_index --manifest data/tgtu_corpus/manifest.jsonl --archives /path/to/tgtu_drive_archives
```

Индексатор сверяет SHA-256, размер и число страниц каждого PDF перед добавлением.
Он индексирует 542 научные статьи, исключая три помеченные записи. Аннотации
161 совпавшей статьи из старого корпуса добавляются для поиска по русскому и
английскому тексту. Источником для чтения и цитирования остаётся PDF из ZIP;
страница `/citations/sources/<id>/pdf/` отдаёт именно проиндексированный файл.

Индекс хранится в SQLite и пересоздаётся атомарной заменой. Автоматическая
сборка при первом запросе разрешена только для небольшого старого корпуса:
расширенный индекс готовится заранее, чтобы пользователь не ждал обработки
тысяч страниц. Если ZIP недоступен, готовность индекса снимается и PDF не
выдаётся по сломанной ссылке.

## Локальные модели

Для анализа утверждений и реранкинга используются общие настройки
`AI_PROVIDER=openai_compatible`, `AI_BASE_URL` и `AI_MODEL`.

Для настоящих dense embeddings задаются:

```dotenv
CITATION_EMBEDDING_BASE_URL=http://127.0.0.1:8080/v1
CITATION_EMBEDDING_MODEL=bge-m3
CITATION_EMBEDDING_API_KEY=
```

После смены embedding-модели индекс нужно перестроить.
